# PDF 导出与检查

本入口用于作者明确要求的本地 PDF 导出。系列版式见总控 `standards/pdf.md`，独立书仓对应 `tools/standards/pdf.md`。默认使用 Pandoc＋Typst 的 A5 标准版；手机版是明确选择的实验配置，不默认同时生成。

## 1. 固定输入

先确认作品、正文提交 C、正文版本 `vYYYY.MM.N`、两位或以上导出号，以及所需阅读配置。C 可以通过提交或标签指定，工具记录解析后的完整提交；不得隐式使用当前工作区正文。版本与导出号不代替来源提交。

从 C 取得的 `book.yaml` 必须启用 `outputs.pdf.enabled`；正文、章节顺序、主语言和采用图也以 C 为准。当前 PDF 仅支持主语言；可省略 `--language`，显式指定时必须与主语言相同，不与自动繁简转换合用。其他语言的离线阅读构建已经可用，不代表对应 PDF 已接通。

确认当前调用方的工具与模板快照。正文来自 C，但实际执行的是此次调用的工具，二者分别记录摘要；若需要复现旧导出，应取回旧回执所记录的工具、模板、参数和字体，而不只取回正文 C。

## 2. 选择配置

| profile | 默认行为 | 使用范围 |
|---|---|---|
| `standard` | A5、正文11pt、上下18mm/左右16mm、代码8.6pt、表格9pt；黑白灰、精简一级纸面目录和详细书签 | 系列默认阅读版 |
| `mobile` | 90×160mm、正文11.5pt、上9mm/下12mm/左右7mm、代码9pt、表格9.5pt | 实验校样；独立检查，不能沿用标准版验收 |

作品配置位于 `book.yaml.outputs.pdf`，来自 C；命令行的 profile 和日期可覆盖此次导出参数。

| 配置键 | 本版含义与默认值 |
|---|---|
| `enabled` | 必须为 `true` 才允许导出 |
| `profile` | 未显式传 `--pdf-profile` 时采用；未配置为 `standard` |
| `paper` | 标准版默认 `a5`；兼容显式 `b5`、`a4`，需另行验证；手机版固定90×160mm |
| `body_font` / `font` | 正文字体；`body_font` 优先，`font` 为兼容键 |
| `heading_font` / `code_font` | 标题字体默认正文同款；代码默认 `Sarasa Mono SC` |
| `font_paths` | 书仓内字体目录列表；设定后仅使用这些目录中的字体，并记录文件SHA-256 |
| `toc` / `toc_depth` | 书籍默认打印目录，教程默认不打印；目录默认1层 |
| `bookmark_depth` | PDF书签默认4层；与纸面目录深度分开 |
| `figure_appendix` | 默认 `false`；启用独立大图附录及双向跳转 |
| `author` / `subtitle` / `series_title` | 署名、副标题与系列名；须核对实际取值，不写不存在的出版信息 |

字体必须在实际构建环境可用。无 `font_paths` 时为系统字体发现，回执明确记录字体源文件尚未固定；不能只凭字体名称宣称完全可复现。模板的完整默认值以随书 `FORMAT.md` 及实际导出回执为准，不能复制另一引擎的参数名后假定生效。

当前版式为 `series-pdf-v1.1`：正文11pt保持，行间边缘间距0.68em、段距1.15em；标准版标题21/15/12/11.5pt，手机版19/14/12/11.5pt。图注9.5pt深灰左对齐，提示只保留细线。常规图片与明确配对的图说明同页，按比例放进116×110mm（标准）或76×80mm（手机）的上限，不固定占满高度；实际宽度还受纸张配置影响。高度上限不代表标签可读，缩小后仍需检查。长表按行分页，同一行默认不拆页；单行太长时需编辑调整。

书籍使用封面、来源页、精简目录与章节分页；`type: tutorial` 使用相同视觉体系的简化结构。可选 `figure_appendix: true` 保留大图附录，但正文图片仍须可读。不要为修复版式直接改写某一章的内容语义、裁图、删表列或把代码转换成图片。

## 3. 执行导出

在总控根目录运行，以下 `WORK`、`C` 和编号须换成本次实际值：

```sh
python3 tools/studio.py build WORK --pdf --source C --version v2026.09.1 --export-id 01 --pdf-profile standard --export-date 2026-09-26
```

在独立书仓省略作品 ID：

```sh
python3 tools/studio.py build --pdf --source C --version v2026.09.1 --export-id 01 --pdf-profile standard --export-date 2026-09-26
```

需要手机版时另用新导出号：

```sh
python3 tools/studio.py build WORK --pdf --source C --version v2026.09.1 --export-id 02 --pdf-profile mobile --export-date 2026-09-26
```

`--pdf-profile` 省略时使用 C 的配置，未配置则为 `standard`。导出日期写入来源页与回执，省略时采用构建当天日期；要固定日期应显式传入。一次调用只生成一个阅读配置；不要把另一配置的文件放进已验收目录冒充同次产物。

构建依赖 Pandoc、Typst 和所选字体。必要工具缺失、字体不可用、源检查失败或编译失败时停止，按诊断修复后重试；普通构建不联网下载字体、模板或图片。历史 Mermaid 资源还需随书已经锁定的渲染器与浏览器，新手绘图直接复用采用稿，不触发图像服务。

## 4. 读取产物与回执

导出目录为作品内的 `build/pdf/<正文版本>/<导出号>/`，包含 `<作品>-<正文版本>-<导出号>-<profile>.pdf`、`export.json` 和 `qa.json`。成功后核对命令返回的实际文件路径；不要凭同名文件、修改时间或体积判断成功。已有导出号拒绝覆盖。

回执应能回答：

- 正文来自哪个完整 C，章节顺序、语言、正文版本和导出号是什么。
- 实际运行哪个 Pandoc、Typst、工具文件和模板，生效的 profile 与版式参数是什么。
- 哪些图片进入 PDF，输入文件摘要是否对应 C 的采用稿；字体实际解析和文件摘要哪些已记录、哪些未知。
- 哪个 PDF 是本次结果，文件名与 SHA-256 是否匹配；日志、机械检查和视觉审阅分别处于什么状态。

构建诊断在 `build/pdf-work/<正文版本>/<导出号>/`，保存 `commands.json`、固定来源与中间文件的 `source/`、实际调用方工具与模板的 `caller-tools/`、输入文件摘要 `input-files.json` 及已产生的QA结果。`source/code-sources.json` 保留本次构建的原始代码块与行内代码（含节点类型和顺序），用于与PDF复制结果核对；它不是PDF复制已通过的证明。进入构建后的失败另存失败回执；预检尚未进入构建时以命令错误输出为准，不声称已有诊断文件。

构建会将来源正文与排版适配后的普通代码块、行内代码逐项比对，内容或顺序变化则停止；历史 Mermaid 图块单独按图处理。参数、日志和输出绑定同一次导出。诊断目录中的半成品不能当成成功交付。不要删除失败现场来继续使用相同编号，也不要复制旧 PDF 到新目录“补齐”结果。

## 5. 运行独立 PDF 检查

`pdf-check` 接收实际 PDF 文件路径，不要求作品 ID；可检查已有文件，不重新导出、不回改书稿。

```sh
python3 tools/studio.py pdf-check /absolute/path/to/book.pdf
python3 tools/studio.py pdf-check /absolute/path/to/book.pdf --render --output /absolute/path/to/pdf-review
python3 tools/studio.py --json pdf-check /absolute/path/to/book.pdf
```

纯扫描不写文件，`--json` 在标准输出返回完整报告。检查依赖 `pypdf`、`pdfplumber`；`--render` 另需 Poppler 的 `pdftoppm`，并要求显式传入 `--output`。

先读实际检查项、PDF SHA-256 和问题页定位。当前 `--render` 最多生成12张代表页PNG：前三页、末页及错误/稀疏候选页；输出目录不自动保存报告JSON，也不生成全书缩略图。已有同名校样不覆盖。它只是查看入口，不代表全书已渲染或已经有人目视。缺少依赖时记录未完成项。

报告包含页尺寸/裁切框、文字纸外越界候选、字体嵌入、链接目的地、残留本地链接及空白/低密度页候选。目前不遍历书签树，书签层级和跳转另行检查。其 `visual_review` 始终为 `pending`，即使扫描和渲染成功也不改变。

机器报告不能替代以下检查：

1. 先看整书页面总览，检查目录长度、章节顺序、异常空白和分页节奏。
2. 足尺查看封面、来源页、目录和章首；重点核对页码、页眉是否在纸内，标题是否孤立。
3. 核对跨页代码、长 URL、中文注释和长提示词；复制代表命令到纯文本中比较内容、缩进和逻辑行。模板的视觉折行不插零宽字符，但阅读器仍可能复制出额外换行；遇到这种情况记录限制，并使用本次绑定的原始代码核对。
4. 核对跨页长表、宽表、重复表头和全部图片；图注应在附近，图内关键文字在实际版心可读。
5. 实际点击目录、不同层级书签、跨章链接以及启用的大图附录双向链接；目标存在还要确认内容正确。
6. 手机版按约390px页面宽查看，并另记是否使用真实手机/PDF阅读器验证。没有实测不写“手机通过”。

文字边界、少字页等机器候选先回看再判断；不要自动删除可能的封面、分部页或图片页。报告未列出的项目不视为已检查。

## 6. 记录视觉结论与交付

新导出默认视觉待审。实际检查记录绑定 PDF SHA-256、profile、审阅者、日期、所看范围、使用环境、问题与结论。未完成整书巡检时明确列出已看页，不能把代表页通过写成全书通过；可访问性与读屏也分别记录。

只有实际通过后才更新该文件对应的 `export.json` 视觉状态；机器检查不能自动将 `visual_review` 改为 `pass`。若修改 PDF 或重新生成，即使书名与页数相同，也要重新核对摘要和审阅结论。不要复制历史回执或篡改旧导出摘要。

本地交付至少说明来源 C、正文版本、导出号、profile、文件路径、实际检查范围和未完成项。版式修复后用新的导出号生成，保留旧结果，便于回看差异。

本地导出不构成上传授权。另有公开授权时，继续执行随书发布流程；`release prepare` 仍检查 PDF 与旁边 `export.json` 的文件名、来源和 SHA-256，视觉未通过不能准备公开。延后导出版使用 `pdf-<正文版本>-NN`，指向原 C，不抢正文 latest，远端下载核对后才更新读者入口。

## 7. 模板升级与回归

单书模板和工具是固定快照。升级先比较本地定制，保留已有代码折行、跨页、固定源链接与大图附录能力；不能用总控新版直接覆盖而跳过检查。

至少用中文长段、中英混排、长代码/URL、中文注释、宽表、跨页长表、横竖图片、图注、提示、脚注和跨章链接组成难排样章。对比新旧页面、复制与跳转；再执行授权范围内的整书导出。每种 profile 独立验收，标准版通过不能顺带标记实验手机版通过。

阅读配置、工具/模板升级与正文事实更新分别记录。一般修正文稿不自动换引擎；当前保持 Pandoc＋Typst，借鉴其他项目的参数组织和检查方式，不引入隐式联网或第二套默认生成机制。

PDF适配仅将一级引用块开头的装饰性💡/⚠标记转成黑白“提示/注意”文字；已有【主线/支线】明文标签时去掉相应🎯/🌿装饰。代码围栏、引用内围栏、缩进代码和行内代码不改写，普通正文中的表情不参与此规则，遗留正文的其他彩色表情仍需在整书校样时核对。

## 作者彩色头像

来源提交有 `book.yaml.branding` 时，按该提交中的本地头像和摘要导出，回执登记 `author_branding`。`series-pdf-v1.2` 封面与正文页眉接入彩色头像，采用 `tools/standards/branding.md`。旧来源未登记头像时保持旧行为；不能用工作区或总控照片补入历史版本。标准/窄版均需查看实际页眉与正文间距。
