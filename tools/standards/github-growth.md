# GitHub 运营规范 · 1.1

适用于「普通人的 AI 工具入门系列」所有图书、独立教程和系列入口。目标是让需要的人找到内容、开始阅读、愿意收藏和推荐。运营依据实际可读内容，不改变产品事实、许可和既有书稿验收。

## 每个作品交付一个运营包

运营配置唯一维护在总控 `growth/catalog.json`；章节、顺序、完成情况仍以书内 `book.yaml`、正文和发行回执为准。运营表不成为第二份目录。`private/<id>/growth/` 保存基线、证据、传播草稿、实验和回执；公开仓只收读者文案、采用图片及可公开来源说明。

作品状态分 draft / public。public 必须有真实公开仓库和可读起点；正文在写、目录占位和本地建仓都不等于已出版。系列导航只推荐已公开且适合当前读者的作品。元数据是拟采用配置，远端是否应用另记回执，不能由配置倒推出已经上线。

## 被找到与看懂价值

- 不为关键词改掉既有仓库地址。新地址优先准确产品英文名 + guide/tutorial + 必要读者限定；存在重名时再选，不猜可用性。
- About 简介采用「产品 + 读者 + 实际任务 + 内容形态」。可加一句简短英文用途。可在稳定定位后加已发布且有正文支撑的当前模型名称和用途；避免堆词、易变图数、无证据的全网第一或零成本承诺。项目约定不超过 350 字符。
- Topics 选真实产品、学习用途、读者与语言，一般 6—10 个足够；平台最多 20 个，每个最多 50 个小写字母、数字或连字符。删除不再适用的版本标签，不把热词用满当成优化。
- README 第一屏先回答适合谁、能解决什么、从哪开始。主动作是直接阅读，无需先 clone 或安装 Git。核心信息用可搜索正文，图片不能代替文字入口。
- 一张轻量横幅、一条主阅读入口、两三个按需求选的入口即可。长目录可折叠，完整目录和生成器标记原样保留。手机内容宽约 358px 时检查标题和按钮换行。
- 展示真实章节、案例或结果，不把编写中的规划写成已完成效果；中文内容不挂没有正文的 English coming soon 入口。

## 当前价值与新模型入口

首页面向正在寻找教程的人，围绕“适合我、现在能用、值得读、值得收藏”组织。可以突出“2026 年 9 月更新”这类真实的当前更新，但不再用“看过四月版的人怎么办”、过时模型专题或历史 PDF 下载占据首页入口。历史资料与来源说明保留在专门记录中，不删除真实历史，也不把旧文件包装成当前成果。

模型或功能改变了读者的选择、任务、步骤或费用，并已有可读内容承接时，可进入简介和首屏。模型名后紧接具体问题或收益，提供直接阅读入口；未完成、不可核验或与本书无关的热点不进入宣传。书名和长期封面保持稳定，当前重点随内容维护轮换，关键词不用重复铺满页面。

GitHub 默认仓库搜索查名称、简介和 Topics；README 需用 `in:readme` 纳入。因此当前模型词可进入 About 的简短用途句，不能把只改 README 说成改善默认搜索匹配，更不承诺排名或增长。[官方搜索规则](https://docs.github.com/en/search-github/searching-on-github/searching-for-repositories)

首页短介绍、书前普及导读、详细章节分别承担“看到价值、理解关系、学会使用”。前言围绕普通人的任务解释新能力，详细参数、费用表和操作集中在对应章节；不为每次换代重排全书。纯新手与已有基础的人各有适合前置的入口。详细写作规则见 [编辑规范](editorial.md)。

相关更新同步核对正文、前言、README 各语言、About、必要 Topics 和更新说明。只改变排版不刷新全书事实核验日期，语言导览不代表完整译本。没有内容可承接时先修稿；当期重点过时后移出首页，归档记录保留日期。

## 收藏、信任与回访

Star 提示解释读者收益，例如「读完觉得有用，欢迎点右上角 Star 收藏，方便下次查阅」。每页通常一次，长首页最多两次；不在每章塞请求，不虚构可直接完成 Star 的链接。

更新通知另说明 Watch → Custom → Releases。Star 是收藏/认可，不承诺自动收到更新。当前适用范围与核验说明保持可达，可简写后链接详情或放入折叠区；免费阅读与产品账号费用分别说明。许可按实际文件标注，含非商业限制时不笼统承诺任意使用。

纠错入口让读者提交章节、现象和脱敏信息。已有 Issue 模板先复用，不另建重复系统。纠错被采纳后在更新说明致谢，个人信息与署名按对方公开意愿处理。

## 封面与传播图片

沿用 notebook-pen-v1：不透明细方格纸、黑色中性笔手绘、黑白与中性灰。不同作品用产品名、书名和任务图形区分，不自行改成另一套彩色风格。

三种用途分别排版：README 横幅重可读与体积；Social preview 为 1280×640、PNG/JPG/GIF 且小于 1MB；竖版书封仅在图书导出/分发确有需要时制作。两种横版可在构图都适用时共享同一文件。Social preview 需在仓库 Settings 的 Social preview 单独上传，提交 README 图片不会自动设置它。

长期封面只放稳定标题、一句收益、系列与作者；版本数字放文字状态。图片保留替代文字、制作提示词、来源、摘要和目视检查。新图用新文件名，不覆盖历史版本。生成服务负责画面；尺寸、格式及灰阶导出可机械规范化，不凭像素检查代替看图。书内教学图仍走原有 FIG 机制；`assets/social/` 的封面不冒充教学图或操作证据。

## 系列互链

每本书保留「系列教程」入口。总目录未建立公开仓时可使用书内 `docs/系列教程.md`，它只含已核对的公开作品。以后有真实总目录再统一替换，不先发布不存在的链接。

正文推荐 0—3 个相关作品，说明「先学」「接着学」或「遇到什么需求再看」。不强行凑数量，不让所有仓库互相堆链接。只有一本公开书时如实只列一本；草稿不接受导流。关系在 catalog 的 related 中登记，并由维护者核对推荐理由；公开后才启用。

## 发布与复盘

每次新书、实质更新、名称/阅读入口/完成状态变化都核对运营包。小幅纠错不要求重做封面。起草→事实校对→本地检查→按已有授权公开→回读远端→记录状态。具备已有明确授权时连续执行；没有外部发布授权时先完成具体可审阅产物，不把每一步拆成审批。

推广帖子和回复仍按具体渠道授权发送；批量向无关项目发 Issue、买 Star、刷互动不属于本机制。阶段性目标先从真实基线制定，不承诺 Trending 或保证 Star 数。

`python3 tools/growth.py --root . check` 为离线机械检查；不代替读者体验、当前远端可访问性或全文事实审核。`snapshot --work <id>` 显式只读采集 GitHub；无数据记未知，不填零。指标口径与节奏见私有总控的 `docs/GitHub运营机制.md`。

## 中英文作为默认产品能力

2026-09-25 作者追加要求：后续作品默认提供中文和英文，运营同步支持两种语言。坚持一本作品一个仓库，中英文共享 Star、Issue 和版本关系；仅语言变化不另建同书仓库分散积累。

默认根 README.md 提供中文，README.en.md 提供英文；如某作品以国际读者为主，可在明确读者选择后调换默认语言。两个入口顶部都有语言切换。正文保持各自目录与对应章节映射；不要仅为运营而搬动现有章节地址。未来多语言目录由正文生产机制管理。

运营表 locales 分别登记 zh-CN/en 的 status、readme_path、start_path、cover。published 表示该语言已可完整阅读；overview 表示仅介绍页可读、正文尚不具备对应语言；draft 不进入公开语言切换。语言发布与最近内容核验独立记录，不能因中文修订自动给英文打上最新状态。简体、繁体与英文分别管理，不把繁体生成等同于英文翻译。

英文运营文案须按英语读者习惯改写标题、收益、搜索词与CTA；不机械逐句翻译中文营销表达。示例：中文「不会编程，也能从第一次对话开始」，英文可写「A practical Claude Code guide for people with no programming experience」。所有承诺仍由同一作品事实支撑。英语介绍页链接中文章节时显著标注 Chinese，不能做成伪英文入口。

公共入口共用中英并列横幅；按渠道需要再制作语言专用传播图、alt文本与草稿，保持同一纸底、笔触和构图语言，文字需重新排版。GitHub单仓只有一组About与Topics，以及当前一张Social preview，不按访问语言自动切换：About用短中英组合，Topics混合真实产品/任务/语言词；仓库分享图默认采用中英短标题的共同预览，语言专用图片供相应渠道帖子；正文语言状态单独如实说明，实际上传后再核对。

系列页提供中英文对应入口，标注每种语言的完整/导览/筹备状态。英文导流优先指向英文可读成果；只有中文全文时，英语文案提前说明。未来自有阅读站另处理语言URL、canonical与hreflang，不能声称只改GitHub README就实现这些站点能力。

数据能按README.en.md等热门路径做有限观察，不能从GitHub原生UV推断读者语言或按语言分配Star。每种语言的传播记录保存渠道、目标入口与内容状态；没有对应统计就写未知。

## 随书快照的作用域

复制到独立书仓 tools/standards/ 后，本规范仅用于本书读者页面、视觉、真实语言状态与导航规则。文中的 growth/catalog.json、private/、tools/growth.py 及 docs/GitHub运营机制.md 均属于私有总控，在总控执行；不要求独立书仓携带这些文件或访问其路径，也不能复制私有运营记录到公开仓。独立书仓的阅读、check/build 仍使用自身正文配置与工具快照。

## 公共封面与浏览器语言（2026-09-25 补充）

作者要求公共封面同时能让中文和英文读者辨认。公共图用产品英文名＋中文书名＋英文副标题；当前语言说明采用「中文正文 · English overview」，不用纯英文 Chinese guide 代替中文提示。英文全书真正上线后再改为「简体中文 / English」。正文各语言仍有独立入口；渠道专用图可另排版，但公共仓库封面默认双语。

GitHub标准仓库页不提供按浏览器语言选择README的机制，README不能运行识别语言的脚本；语言切换使用显式链接。Social preview为单一仓库图片，不跟随浏览器语言自动切换。未来如建设GitHub Pages阅读站，可读取navigator.languages进行首次语言推荐，优先尊重URL显式语言与读者手动选择，保留持久化切换；不按IP猜语言，不将所有中文用户混同于简体中文偏好。缺少对应语言正文时回到明确的语言选择页，不把中文内容伪装成英文。

中英文页面宜有各自固定URL及预先生成的分享meta/封面，分享抓取程序不能依赖浏览器脚本。两种语言的Star统一回到原书仓库，不因语言拆仓。以上为阅读站方案，本轮未建立或部署该站点。

依据：[GitHub官方README渲染与脚本清理](https://github.com/github/markup)、[GitHub Pages](https://docs.github.com/en/pages/getting-started-with-github-pages/what-is-github-pages)、[navigator.languages](https://developer.mozilla.org/en-US/docs/Web/API/Navigator/languages)。
